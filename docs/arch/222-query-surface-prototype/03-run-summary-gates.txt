# GATE ROWS. A gate spawns nothing (#214), so TASKS, USAGE and DURATION are all
# `-`, and its STATE is the verb the orchestrator used, not a task projection:
#
#   waiting | approved | rejected | redirected | finished
#
# So the node table's STATE column is polymorphic - a projection over tasks for
# a step, a verb for a gate. That is not a wart: it is #214's "a node is either
# a step or a gate" surfacing exactly once, in the one column where the two
# kinds differ.
#
# The gate's GIST is its declared `question`, truncated, plus the verb and its
# argument. A rejected gate reads `-> reject (on_reject: implement)`; a
# redirect names the node the orchestrator chose. The `--note` from #221 is
# NOT shown here - it went into the entry task's prompt, and the summary is
# not where you read prompts.
#
# A gate still waiting reads:
#
#   rework-or-finish  2     waiting     -      -            2m10s...  "Send it back, or finish here?"
#
# and DURATION becomes the only non-`-` column, because how long a gate has
# been sitting on the orchestrator is the single most actionable number in the
# whole view.
