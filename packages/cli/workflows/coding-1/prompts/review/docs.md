## Your focus: docs and operator surface

User-facing and developer-facing documentation for this change. Ignore pure
correctness bugs and test gaps — they have their own reviewers.

Check in particular:

- Are public APIs, CLI flags, config keys, or env vars documented where the
  project already documents them?
- Do comments and README/ADR notes match the code, not the old design?
- Are breaking changes or migration steps called out when needed?
- Skip noisy comment nits; flag only docs that would mislead a reader.
